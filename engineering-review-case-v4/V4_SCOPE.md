# V4 Scope: Small Engineering Review Case

Date: 2026-04-28

## 1. Why V4 Exists

V1 to V3.2 established a staged diagnostic chain:

```text
V1: static relation internalization
V2: delayed temporal relation internalization
V2.1: reviewer hardening against fixed templates and shortcuts
V3: partial observability, noisy delayed observations, and takeover
V3.1: takeover hardening against overcautious templates
V3.2: longer and correlated partial-observability stress tests
```

V4 should not add another toy metric for its own sake.

V4 should test whether the relation-chain machinery can be expressed as a
bounded engineering review workflow.

## 2. Core Question

```text
Can the system review a small slope-engineering plan by naming the causal chain,
the action points, the uncertain links, the verification indicators, the takeover
conditions, and the human responsibility boundary?
```

## 3. What Counts As Success

A V4 review succeeds only if it identifies:

```text
key variables
time-indexed or process relation chain
action effect points
missing or uncertain observations
verification indicators
failure conditions
human takeover conditions
responsibility chain
claim boundary
```

Generic text such as:

```text
strengthen drainage and support
increase monitoring
pay attention to safety
```

does not count unless it maps those actions onto explicit relation links.

## 4. Case Type

Use small curated toy cases, not real project data.

Each case may include:

```text
site_context
observed_conditions
monitoring_state
proposed_actions
known_relation_chain
known_uncertainties
expected_review_points
unsafe_review_patterns
```

## 5. Supported Claims After V4

If V4 passes, the project may claim:

```text
The relation-internalization diagnostic can be expressed as a bounded engineering
review workflow in toy slope-style cases.
```

It may also claim:

```text
Generic engineering language and high prediction scores are insufficient without
relation-chain audit, uncertainty audit, takeover conditions, and responsibility
boundaries.
```

## 6. Unsupported Claims

V4 must not claim:

```text
real geotechnical correctness
real slope safety prediction
real construction-plan approval
deployment-ready engineering AI
expert replacement
unrestricted engineering relation discovery
```

## 7. Stop Conditions

Stop and write a limitation instead of expanding if:

```text
the review becomes generic engineering prose
the case requires real design-code interpretation
the model starts making safety recommendations as final decisions
the scoring rewards fluent text rather than relation-chain specificity
negative controls pass the gates
```
